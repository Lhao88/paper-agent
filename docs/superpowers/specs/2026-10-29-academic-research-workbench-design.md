# 学术调研多 Agent 工作台：已确认设计

日期：2026-10-29  
状态：产品方向、四类 Agent 和分层阅读方案已获用户认可。本文补充的工程规则属于实施建议。

## 1. 项目目标

面向研究生和高校科研人员，用户输入研究主题后，由多个 Agent 协作完成研究规划、论文检索、摘要筛选、全文精读、综合分析和综述生成。最终成果可以在线查阅、追溯引用并导出。

项目当前用于毕业设计或项目立项。核心研究问题是：如何通过多 Agent 分工和动态阅读深度，在有限时间与调用预算内完成有证据支持的调研。

## 2. 已确认的设计决策

| 编号 | 决策 | 原因与取舍 |
| --- | --- | --- |
| D1 | 使用协调、检索、阅读、综述四类 Agent | 保留明确分工，减少独立角色的协调成本 |
| D2 | 先基于标题和论文原始摘要进行初读，再选择全文精读对象 | 避免对大量候选论文先做全文处理 |
| D3 | 综合分析能力合并到综述 Agent | 保留跨论文归纳与比较，减少一次角色交接 |
| D4 | 首版不设置独立研究审校 Agent | 保留引用检查、证据完整性检查和综述自检；自检不视为独立验证 |
| D5 | 通过共享研究资料交接结果 | 后续 Agent 能访问原始证据，减少摘要反复转述造成的信息丢失 |

## 3. Agent 分工

| Agent | 输入 | 工作内容 | 输出 |
| --- | --- | --- | --- |
| 研究协调 Agent | 主题、用户约束、任务状态 | 拆解子问题、制定计划、调度任务、决定补检、管理预算 | 研究计划、任务清单、阶段状态 |
| 文献检索 Agent | 子问题、检索范围 | 生成检索式、调用数据源、去重、执行明确条件过滤 | 论文元数据、原始摘要、来源与检索记录 |
| 文献阅读 Agent | 论文和研究子问题 | 执行摘要初读或全文精读两类任务 | 筛选卡片、精读卡片、原文证据 |
| 综述 Agent | 精读卡片、证据、研究计划 | 综合分析、方法比较、生成大纲、撰写章节和基础自检 | 分析材料、综述、引用及待核验项 |

角色与运行实例分离：可以同时运行多个阅读实例。并发数受配置和预算约束，不要求四种不同基础模型。

## 4. 研究流程

输入主题 → 生成可编辑研究计划 → 检索候选论文 → 去重和条件过滤 → 摘要初读 → 排序及覆盖选择 → 全文精读 → 综合分析 → 生成综述 → 基础检查 → 查阅与导出。

分析阶段发现关键证据缺口时，由协调 Agent 判断是否追加检索或精读。补检与修订必须有轮次、时间和调用预算上限；达到上限后保留已经完成的结果并说明未解决问题。

### 4.1 摘要初读

优先使用论文已有摘要，不为所有论文先下载和解析全文。输出：

- 研究内容的简短描述。
- 对应的研究子问题。
- 相关性判断及理由。
- 处理建议：优先精读、候选保留、排除、信息不足。

无摘要不等同于不相关。对信息不足的记录，结合其他元数据决定是否补充材料，不直接作出研究内容判断。

### 4.2 精读选择

选择依据包含主题相关性、子问题覆盖和内容重复度。引用数量不直接代表论文质量。

可试验的起步配额为约 200 篇候选、60 篇摘要初读、15—25 篇全文精读；这些数值是配置建议，不是用户确认的硬性要求或性能承诺。

筛选记录应保存，用户可以恢复被排除的论文或手动指定精读对象。

### 4.3 全文精读

提取研究问题、方法、数据或研究对象、实验条件、指标、结果和局限。每项用于后续综述的事实关联原文片段和可用的位置标识。

原文未报告的字段明确标记缺失。获取不到全文时保留“仅摘要”状态，不产生全文层面的实验判断。作者陈述与系统推断分开记录。

### 4.4 综合与写作

综述 Agent 先生成研究分支、方法对照表、共识与分歧、证据缺口和大纲，再根据证据撰写章节。不同数据集、指标定义和实验条件下的结果不直接合并排名。

默认成果是主题综述式研究报告，包含背景与范围、概念、研究分支、方法比较、研究进展、局限、调研说明及参考文献。对研究空白的判断限定在本次检索与纳入文献范围内。

## 5. 首版业务要求

| 编号 | 要求 | 验收表现 |
| --- | --- | --- |
| R1 | 研究项目与计划 | 保存主题、子问题、范围和执行状态；用户可调整计划 |
| R2 | 检索与筛选 | 可查看检索来源、筛选理由及最终精读列表 |
| R3 | 分层阅读 | 摘要任务和全文任务明确区分，全文获取发生在选择之后 |
| R4 | 证据与结构化资料 | 精读结果关联原文；缺失信息和仅摘要材料有明确状态 |
| R5 | 综合分析与综述 | 先形成可检查的分析材料，再生成可按章节阅读的综述 |
| R6 | 引用与基础检查 | 引用只能来自项目文献库；关键事实可定位证据；未核验项可见 |
| R7 | 协作与异常处理 | 可查看任务进展、失败原因、预算停止和部分成果，并重试失败任务 |
| R8 | 保存与导出 | 保存综述与参考文献，提供至少一种完整的文本导出格式 |

首版不包含独立审校 Agent、多人协作、自动订阅、大规模引文图或完整的系统综述审计流程。

## 6. 建议的工程规则

- 论文、证据、任务和综述使用稳定标识。预印本与正式发表版本保留关联关系，避免无依据覆盖。
- 共享资料保存原始内容及来源，Agent 的结构化输出需要校验后才能进入下游任务。
- 引用条目存在性由程序检查；语义支持程度仍需模型辅助与人工抽查。
- 任务重试复用已经完成的资料，不重复生成同一成果；任务输出更新不静默覆盖用户修订。
- 论文文本视为待分析资料，不作为工具调用或执行指令。上传资料的可见范围和发送给模型的范围需要明确。
- 对外部服务设置失败状态、有限重试和预算记录；检索来源不可用时披露覆盖限制。

## 7. 毕设评价

比较单 Agent、固定流程多 Agent、带动态精读与反馈的多 Agent。尽量控制模型、初始语料和总预算，单独记录补检新增的资料。

评价检索相关性、关键论文覆盖、摘要筛选漏选、字段抽取正确性、引用支持率、综述质量、耗时和调用成本。人工审核样本独立于开发调参样本；暂不预设未经实验支持的提升幅度。
