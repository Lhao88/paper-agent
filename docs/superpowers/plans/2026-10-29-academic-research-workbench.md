# 学术调研多 Agent 工作台 Implementation Plan

> **For agentic workers:** 执行代码开发时使用 superpowers:executing-plans；只有用户选择代理分工执行后才采用 superpowers:subagent-driven-development。步骤使用复选框跟踪。

**Goal:** 实现从研究主题到带证据引用综述的四 Agent 协作原型。

**Architecture:** 协调 Agent 管理计划和有边界的任务循环，检索 Agent 收集候选论文，阅读 Agent 分层筛选与精读，综述 Agent 综合分析和写作。Agent 通过稳定标识与共享研究资料交接，解析、去重和引用校验作为公共工具。

**Tech Stack:** 尚未选择。本文件是功能实施与验收计划；任务 1 完成后补充代码文件映射、依赖和可执行检查命令，再开始对应代码任务。

**Spec:** [已确认设计](../specs/2026-10-29-academic-research-workbench-design.md)

## Global Constraints

- 使用协调、检索、阅读、综述四类 Agent。
- 摘要初读先于全文精读；不提前全文处理全部候选论文。
- 综合分析能力合并到综述 Agent，首版不设置独立研究审校 Agent。
- 原文未报告的字段明确标记缺失；仅摘要材料不能生成全文层面的实验判断。
- 补检与修订有轮次、时间和调用预算上限。
- 不主动执行 git commit、git push；不批量删除文件；保留用户已有改动。
- 技术选型和建议配额不是已确认约束，不编造现有目录、接口或检查命令。

## Review Focus

1. 无摘要论文：保留信息不足状态，不能自动判为不相关，归任务 3 验证。
2. 重复记录与不同版本：去重保留来源，不覆盖版本差异，归任务 2 验证。
3. 无法获得全文或解析失败：保留材料状态和部分结果，归任务 4 验证。
4. 外部服务超时、执行中断或预算耗尽：有限重试，可恢复，停止后可查看成果，归任务 6 验证。
5. 引用条目存在但证据不支持结论：不把结构校验当成语义验证，归任务 5 和任务 8 验证。

## 计划边界与文件映射

当前工作区未发现 README、依赖清单或已有实现。本次仅新增设计与计划文档。

代码阶段需要形成以下职责模块，具体语言和文件路径在任务 1 中落实：研究项目与任务状态、数据源适配、论文去重、摘要筛选、全文获取与解析、证据存储、综合与写作、引用检查、任务调度、工作台界面、评价用例。

在框架未选择且依赖未建立前不填写虚构的测试命令。每个代码任务开始前，先根据实际依赖清单确定命令，并补充到本计划。

## 跨模块资料约定

以下是逻辑资料契约，不是已经存在的代码类型。

| 对象 | 必需信息 | 主要生产者与使用者 |
| --- | --- | --- |
| ResearchPlan | project_id、topic、questions、scope、budgets、version | 协调 Agent → 所有研究任务 |
| PaperRecord | paper_id、identifiers、title、abstract及缺失状态、sources、version_links | 检索 → 阅读 |
| ScreeningCard | paper_id、matched_question_ids、relevance_level、reason、decision、material_basis | 阅读初读 → 精读选择 |
| EvidenceRecord | evidence_id、paper_id、原文片段、可用位置标识、来源版本 | 阅读精读 → 综述 |
| ReadingCard | paper_id、结构化研究字段、字段对应evidence_id、缺失项 | 阅读精读 → 综合分析 |
| SynthesisArtifact | 主题分组、对照表、结论及证据关联、分歧、缺口、大纲 | 综述分析阶段 → 写作阶段 |
| ReviewArtifact | 章节、事实与证据关联、参考文献、覆盖范围、待核验项、版本 | 综述 → 展示与导出 |
| TaskRecord | task_id、project_id、role、inputs、dependencies、status、attempts、outputs、usage、error | 调度 → 执行与界面 |

## Task 1：确定可实施的最小环境

**产出：** 可运行的项目入口、真实的依赖清单，以及本计划的代码文件映射。

- [ ] 确定开发语言与界面框架、一个模型服务和最小数据源组合，记录选择依据与配置方式。
- [ ] 用一组真实主题检验数据源的摘要可用性、全文可得性与接口额度；记录失败样本。
- [ ] 建立配置样例、依赖清单和 README，凭据从配置读取。
- [ ] 确立资料契约和状态枚举，并补充各模块真实路径。
- [ ] 按实际依赖清单补充启动和验证命令，执行最小连通性检查。

## Task 2：检索与可追踪的候选论文库

**输入：** ResearchPlan。**输出：** PaperRecord 集合及检索记录。

- [ ] 建立重复 DOI、多来源同论文、无 DOI、预印本与正式版的验收样本。
- [ ] 实现数据源适配、检索记录和明确条件过滤。
- [ ] 实现规范化与去重，保留来源和版本关联。
- [ ] 验证同一论文不会重复分配任务，不同版本不会静默覆盖。
- [ ] 验证检索来源失败会显示范围限制，不被呈现为完整检索。

## Task 3：摘要初读与精读名单

**输入：** ResearchPlan、PaperRecord。**输出：** ScreeningCard 和精读选择记录。

- [ ] 建立相关、不相关、无摘要、多子问题和高度重复内容的样本。
- [ ] 实现阅读 Agent 的摘要初读输出及结构校验。
- [ ] 实现兼顾相关性、问题覆盖和重复度的选择策略，配额配置化。
- [ ] 保存筛选理由，并允许用户恢复候选论文或指定精读。
- [ ] 验证筛选前不会批量下载或解析全文，无摘要记录不会被自动判定不相关。

## Task 4：全文精读与证据记录

**输入：** 精读名单、PaperRecord。**输出：** ReadingCard、EvidenceRecord。

- [ ] 建立全文缺失、解析失败、字段未报告、页码不可用的验收样本。
- [ ] 实现选中论文的全文获取和解析，保留文件版本与来源。
- [ ] 实现结构化抽取，将事实字段与证据位置关联。
- [ ] 区分原文事实、作者观点、系统推断和信息缺失。
- [ ] 验证仅摘要记录不会伪装成已精读，解析失败保留可查看的部分成果。

## Task 5：综合分析与综述生成

**输入：** ResearchPlan、ReadingCard、EvidenceRecord。**输出：** SynthesisArtifact、ReviewArtifact。

- [ ] 建立不可比指标、相互矛盾结论、缺失证据和错误引用的验收样本。
- [ ] 先形成主题分组、对照表、分歧、缺口和大纲，并保存分析成果。
- [ ] 根据章节对应证据生成综述，参考文献条目取自论文库。
- [ ] 实现引用条目和证据关联检查，生成待核验项。
- [ ] 实现综述 Agent 的基础自检，记录自检意见，不将其作为独立质量证明。
- [ ] 验证不可比结果不被直接排名，研究空白表述限定于本次材料。

## Task 6：协调、预算和恢复

**输入：** 研究计划、各阶段资料及状态。**输出：** TaskRecord、阶段结果和补充任务。

- [ ] 建立服务超时、重复重试、中断恢复、预算耗尽和补检循环的验收场景。
- [ ] 实现依赖调度、可配置的阅读并发、有限重试及用量记录。
- [ ] 让协调 Agent 将具体证据缺口转为补检或精读任务。
- [ ] 限制补检与修订轮次，停止时保留未解决问题和已有资料。
- [ ] 验证重试复用已有结果，不重复执行已完成的全文阅读或覆盖用户修订。

## Task 7：工作台查阅与导出

**输入：** 项目资料、TaskRecord、ReviewArtifact。**输出：** 可操作界面和导出成果。

- [ ] 实现主题输入、计划编辑和执行进度展示。
- [ ] 实现候选列表、筛选理由、精读卡片和原文证据查看。
- [ ] 实现综述章节导航、引用跳转和待核验项展示。
- [ ] 实现失败任务重试和至少一种保留参考文献的文本导出。
- [ ] 验证页面刷新后资料仍可读取，引用跳转指向正确论文与证据。

## Task 8：端到端验证与毕设实验

**输入：** 完整工作台、独立人工审核样本。**输出：** 可复现实验记录和结果报告。

- [ ] 冻结评价主题与论文样本，记录人工相关性判断和证据审核准则。
- [ ] 完成主题输入到综述导出的端到端演示。
- [ ] 比较单 Agent、固定多 Agent、动态精读与反馈三类流程，记录模型与预算差异。
- [ ] 分开统计摘要筛选漏选、精读正确性、引用支持率、综述质量、时间和成本。
- [ ] 人工检查“引用存在但不支持结论”的情况，避免仅用生成模型自评。
- [ ] 记录未达到预期的结果和适用范围，不将原型测试外推为全学科效果。
